# Landing Pages Integration into the Extraconomy Platform

## Objective

Introduce a new dedicated area within the Extraconomy platform for custom landing pages as a marketing service to be offered to clients. This area must allow template selection, preview display, and guided completion of the content needed for personalization.

## New dedicated landing pages area

A specific area for landing pages must be created inside the platform. This section should be clearly recognizable as a standalone service and should present the available templates in a simple and immediate way.

In the dashboard of this area, the available templates must be displayed through three checkboxes, each associated with a preview image of the related landing page. Each checkbox must include a label clearly indicating where that landing page can be used, so the client can more easily choose the model that best matches their goal.

## Template display

For each template, the platform must show:

- template preview image
- selection checkbox
- descriptive label explaining the use case
- ability to view the preview before filling out the form

The checkbox labels should be written in a usage-oriented way, for example:

| Template | Checkbox label |
|---|---|
| landingpage1 | For professionals, local businesses, and services focused on contact generation |
| landingpage2 | For products or commercial offers that need to be promoted and pushed toward conversion |
| landingpage3 | For digital services, workflows, tools, or tech offers that need to be presented in an operational way |

## Template structure

The platform must present the templates according to the following usage logic:

| Template | Main goal | Ideal client | Recommended section order |
|---|---|---|---|
| landingpage1 | Contact / offer presentation | professionals, local businesses, single services, small companies | Hero, Benefits, Intro, Offer Grid, Trust, Flow, Final CTA |
| landingpage2 | Product / commercial offer | brands with a physical or digital product, single offer to push | Product Hero, Problem/Solution, Features, Use Cases, Trust/Reviews, FAQ, Final CTA |
| landingpage3 | Digital service / workflow | digital agencies, tools, tech services, creative or automated packages | Hero, How It Works, Modules/Features, Operational Benefits, Target/Use Cases, Process/Method, Final CTA |
| landingpage4 | Consulting / lead generation | consultants, firms, agencies, senior freelancers, high-value services | Hero, Client Problem, Method, Areas of Intervention, Results/Case Studies, FAQ/Objections, Contact CTA |

## Dashboard usage flow

After the template has been selected and the preview has been viewed, the dashboard must display a dedicated form for that specific landing page. The form should not ask for final ready-to-publish copy, but should instead collect descriptive text that helps the person responsible for personalization and content insertion work more effectively.

Each landing page section must therefore include its own text field where the client describes what they want to include in that block. The idea is that the client fills out a section-by-section brief so that whoever builds the landing page can use that material to write, organize, and adapt the final content.

In addition to text fields, the form must also include the possibility to upload images that may be useful for landing page personalization, such as product photos, team images, logos, settings, screenshots, visual references, or graphic materials that can support the page creation process.

The form must also include brand color selection, so the client can indicate which colors should guide the visual customization of the landing page. This choice should allow the client to specify at least a primary color, a secondary color, and, if needed, a supporting color.

## Field logic

Each section must include guided text fields. Every field should ask the client to describe in a practical way what they want to communicate in that specific part of the page.

The form should be structured in this way:

- one field for each section of the selected template
- free descriptive text input
- focus on desired content, section objective, and useful information for personalization
- possibility for the client to explain what they want to highlight in that block
- possibility to upload images useful for the specific landing page or for overall personalization
- possibility to indicate the brand colors to be used in customization

The goal is not to make the client fill out a fully written landing page, but to collect useful material for the later professional customization process.

## Example of form structure

For each section of the selected landing page, the dashboard should display:

- section name
- short indication of what should be described
- large text field where the client can explain what they want to include

In addition to the fields related to each section, the form must also include:

- image upload area for assets useful to the landing page
- area for logo upload, if available
- brand color selection
- optional field for general personalization notes

Example of completion logic:

| Section | What the client should do |
|---|---|
| Hero | describe the main message, the type of offer, the desired tone, and the action they want the user to take |
| Benefits | explain the main advantages that should be highlighted |
| Intro | briefly describe the service, product, or context of the offer |
| Offer Grid / Features / Modules | describe the elements, services, functions, or parts of the offer that should be presented |
| Trust / Reviews | include elements that help generate trust, such as reviews, numbers, guarantees, or credibility points |
| Flow / How It Works / Process | describe how the service or proposed path works |
| FAQ | list common doubts, objections, or questions that should be answered |
| Final CTA | indicate which final action should be encouraged and with what message |
| Images | upload images useful to show the product, service, team, setting, or visual references |
| Brand colors | indicate the colors to be used in the landing page customization |

## Expected result

With this integration, Extraconomy provides a structured tool to collect requests for custom landing pages. The client selects the most suitable template, views the preview, uploads visual materials, indicates brand colors, and fills in a guided section-by-section brief.

This makes the landing page service clearer, more sellable, and easier to manage both for the client and for the person responsible for content personalization.
